## 1. Overview

The simulation mode generates physiologically plausible biosignal data for testing and development without requiring physical hardware. Both the **Teensy firmware** and the **Open Ephys plugin** can generate simulated data independently.

### When Simulation Runs

| Component | Condition |
|-----------|-----------|
| **Firmware** | Always runs simulation (no real sensors connected yet) |
| **Plugin** | When "Simulation" checkbox is enabled in the editor |

### Sample Rate

All channels are generated at **1000 Hz** (1 ms per sample).

## 2. EEG Signal Simulation

### 2.1 Firmware Implementation

5 channels with different frequencies representing typical EEG rhythms:

| Channel | Frequency | Band | Physiological Meaning |
|---------|-----------|------|----------------------|
| EEG1 | 3 Hz | Delta | Deep sleep, unconsciousness |
| EEG2 | 6 Hz | Theta | Drowsiness, light sleep |
| EEG3 | 10 Hz | Alpha | Relaxed, eyes closed |
| EEG4 | 20 Hz | Beta | Active thinking, focus |
| EEG5 | 40 Hz | Gamma | Higher cognitive processing |

**Signal Characteristics:**
- Amplitude: ~100 µV peak-to-peak
- Waveform: Pure sine wave + random noise (±1000 counts)
- 24-bit resolution with ~0.02235 µV/count

**Code (Firmware):**
```cpp
const float eegFreqs[5] = {3.0f, 6.0f, 10.0f, 20.0f, 40.0f};
float amplitude = 100000.0f;  // ~100µV in 24-bit scale
float signal = amplitude * sin(TWO_PI * eegFreqs[ch] * simTime);
signal += random(-1000, 1000);  // Add noise
```

### 2.2 Plugin Implementation

| Channel | Frequency | Amplitude |
|---------|-----------|-----------|
| EEG1 | 3 Hz | 100 µV |
| EEG2 | 7 Hz | 120 µV |
| EEG3 | 11 Hz | 140 µV |
| EEG4 | 15 Hz | 160 µV |
| EEG5 | 19 Hz | 180 µV |

**Code (Plugin):**
```cpp
double freq = 3.0 + ch * 4.0;  // 3, 7, 11, 15, 19 Hz
double amplitude = 100.0 * (1.0 + ch * 0.2);  // 100-180 µV
eegBuffer[i] = amplitude * sin(2.0 * M_PI * freq * simPhase / 1000.0);
```

## 3. Accelerometer Simulation

Simulates slow body movement and breathing artifacts.

### 3.1 Firmware Implementation

| Axis | Frequency | Amplitude | DC Offset | Description |
|------|-----------|-----------|-----------|-------------|
| X | 0.2 Hz | ±100 mg | 0 | Slow lateral sway |
| Y | 0.15 Hz | ±50 mg | 0 | Anterior-posterior sway |
| Z | 0.25 Hz | ±30 mg | +1g (16384) | Breathing + gravity |

**Code (Firmware):**
```cpp
float accelX = 100 * sin(TWO_PI * 0.2f * simTime);
float accelY = 50 * sin(TWO_PI * 0.15f * simTime);
float accelZ = 16384 + 30 * sin(TWO_PI * 0.25f * simTime);  // Gravity + breathing
```

### 3.2 Plugin Implementation

| Axis | Frequency | Amplitude | DC Offset |
|------|-----------|-----------|-----------|
| X | 0.5 Hz | ±1000 counts | 0 |
| Y | 0.7 Hz | ±1000 counts | 0 |
| Z | 0.3 Hz | ±500 counts | +16384 (1g) |

**Code (Plugin):**
```cpp
auxBuffer[0] = 1000.0f * sin(2.0 * M_PI * 0.5 * simPhase / 1000.0);
auxBuffer[1] = 1000.0f * sin(2.0 * M_PI * 0.7 * simPhase / 1000.0);
auxBuffer[2] = 16384.0f + 500.0f * sin(2.0 * M_PI * 0.3 * simPhase / 1000.0);
```

### 3.3 Physical Interpretation

```
Accelerometer units: LSB at ±2g range
1g = 16384 counts
1 count = 0.061 mg

Example: Z-axis reading of 16384 = device is stationary, Z pointing up
```

## 4. PPG (Photoplethysmography) Simulation

Simulates realistic heartbeat waveforms for Red, IR, and Green LED channels.

### 4.1 Firmware Implementation (Realistic Waveform)

**Heart Rate:** 72 BPM (1.2 Hz)

The firmware generates a physiologically accurate PPG waveform with:
- **Systolic peak**: Sharp rise during heart contraction
- **Dicrotic notch**: Small dip during aortic valve closure
- **Diastolic decay**: Gradual return to baseline

```
PPG Waveform Shape:

Amplitude
    │      ┌─╮ Systolic peak
    │     ╱   ╲
    │    ╱     ╲  ╭─╮ Dicrotic notch
    │   ╱       ╲╯   ╲
    │  ╱              ╲_____ Diastolic decay
    │ ╱
    └─────────────────────────► Time
    │←── 1 cardiac cycle ──→│
         ~833 ms @ 72 BPM
```

**Code (Firmware):**
```cpp
float heartRate = 1.2f;  // Hz (72 BPM)
float heartPhase = fmod(simTime * heartRate, 1.0f);

float ppgPulse = 0;
if (heartPhase < 0.15f) {
    // Systolic rise
    ppgPulse = sin(M_PI * heartPhase / 0.15f);
} else if (heartPhase < 0.4f) {
    // Diastolic decay with dicrotic notch
    float decay = (heartPhase - 0.15f) / 0.25f;
    ppgPulse = cos(M_PI * decay * 0.5f) * 0.8f;
    if (heartPhase > 0.25f && heartPhase < 0.32f) {
        ppgPulse += 0.15f * sin(M_PI * (heartPhase - 0.25f) / 0.07f);
    }
}
```

**Channel Values:**

| Channel | DC Level | AC Amplitude | Wavelength |
|---------|----------|--------------|------------|
| Red | 100,000,000,000 | ±5,000,000,000 | 660 nm |
| IR | 120,000,000,000 | ±6,000,000,000 | 880 nm |
| Green | 80,000,000,000 | ±4,000,000,000 | 530 nm |

### 4.2 Plugin Implementation (Simplified)

Uses simple sine wave approximation:

| Channel | DC Level | AC Amplitude | Frequency |
|---------|----------|--------------|-----------|
| Red | 100,000 | ±5,000 | 1.2 Hz |
| IR | 120,000 | ±6,000 | 1.2 Hz |
| Green | 80,000 | ±4,000 | 1.2 Hz |

**Code (Plugin):**
```cpp
// PPG_Red: 1.2 Hz (~72 BPM heartbeat)
auxBuffer[3] = 100000.0f + 5000.0f * sin(2.0 * M_PI * 1.2 * simPhase / 1000.0);
auxBuffer[4] = 120000.0f + 6000.0f * sin(2.0 * M_PI * 1.2 * simPhase / 1000.0);
auxBuffer[5] = 80000.0f + 4000.0f * sin(2.0 * M_PI * 1.2 * simPhase / 1000.0);
```

### 4.3 PPG Ratio (SpO2 Calculation Potential)

The AC/DC ratio between Red and IR channels can be used to estimate SpO2:

```
R = (AC_Red / DC_Red) / (AC_IR / DC_IR)

Simulated values:
R = (5000/100000) / (6000/120000) = 0.05 / 0.05 = 1.0

SpO2 ≈ 110 - 25 × R = 110 - 25 = 85% (for R=1.0)
```

## 5. Temperature Simulation

Simulates slow body temperature drift.

### 5.1 Firmware Implementation

| Parameter | Value |
|-----------|-------|
| Mean | 36.5°C |
| Variation | ±0.1°C |
| Frequency | 0.001 Hz (1000 second period) |
| Units | Centi-degrees (0.01°C per count) |

**Code (Firmware):**
```cpp
float tempC = 36.5f + 0.1f * sin(TWO_PI * 0.001f * simTime);
int16_t tempValue = (int16_t)(tempC * 100);  // 3650 = 36.50°C
```

### 5.2 Plugin Implementation

| Parameter | Value |
|-----------|-------|
| Mean | 36.5°C (3650 counts) |
| Variation | ±0.5°C |
| Frequency | 0.05 Hz (20 second period) |

**Code (Plugin):**
```cpp
auxBuffer[6] = 3650.0f + 50.0f * sin(2.0 * M_PI * 0.05 * simPhase / 1000.0);
```

### 5.3 Conversion

```
Temperature (°C) = raw_value / 100.0
Example: 3650 → 36.50°C
```

## 6. Battery Simulation

### 6.1 Firmware Implementation

Simulates gradual battery discharge:

| Parameter | Value |
|-----------|-------|
| Starting voltage | 4200 mV (fully charged LiPo) |
| Minimum voltage | 3700 mV (low battery threshold) |
| Discharge rate | 0.01 mV/sample = 10 mV/sec |
| Time to low battery | ~50 seconds (accelerated for testing) |

**Code (Firmware):**
```cpp
float batteryMV = 4200.0f - (simTime * 0.01f);
if (batteryMV < 3700.0f) batteryMV = 3700.0f;
```

### 6.2 Plugin Implementation

Simulates slow oscillation around nominal voltage:

| Parameter | Value |
|-----------|-------|
| Mean | 4000 mV |
| Variation | ±200 mV |
| Frequency | 0.02 Hz (50 second period) |

**Code (Plugin):**
```cpp
auxBuffer[7] = 4000.0f + 200.0f * sin(2.0 * M_PI * 0.02 * simPhase / 1000.0);
```

### 6.3 Battery Level Interpretation

| Voltage (mV) | Charge Level | Status |
|--------------|--------------|--------|
| 4200+ | 100% | Fully charged |
| 4000 | ~75% | Good |
| 3800 | ~25% | Low |
| 3700 | ~5% | Critical |
| <3600 | 0% | Shutdown |

## 7. Sync Signal Simulation

### 7.1 Firmware Implementation

Generates random-interval digital pulses for event synchronization:

| Parameter | Value |
|-----------|-------|
| Pulse duration | 100 ms |
| Interval | Random 500-2000 ms |
| Levels | 0 (low) or 1 (high) |

**Code (Firmware):**
```cpp
static uint32_t nextSyncTime = 0;
static uint16_t syncState = 0;

if (sampleCount >= nextSyncTime) {
    if (syncState == 0) {
        syncState = 1;
        nextSyncTime = sampleCount + 100;  // 100ms pulse
    } else {
        syncState = 0;
        nextSyncTime = sampleCount + random(500, 2000);
    }
}
```

### 7.2 Plugin Implementation

Generates periodic pulses:

| Parameter | Value |
|-----------|-------|
| Period | 1000 ms |
| Pulse duration | 100 ms (10% duty cycle) |
| Levels | 0.0 (low) or 1.0 (high) |

**Code (Plugin):**
```cpp
auxBuffer[8] = (fmod(simPhase, 1000.0) < 100) ? 1.0f : 0.0f;
```

### 7.3 Waveform

```
Sync
  1 │ ┌──┐        ┌──┐        ┌──┐
    │ │  │        │  │        │  │
  0 │─┘  └────────┘  └────────┘  └────────
    └───────────────────────────────────► Time
      │←100ms→│←─ random ─→│
              (500-2000ms)
```

|---------|----------|--------|------------|
| **EEG Frequencies** | 3, 6, 10, 20, 40 Hz | 3, 7, 11, 15, 19 Hz | Different progressions |
| **EEG Amplitude** | 100 µV + noise | 100-180 µV, no noise | Plugin has amplitude gradient |
| **Accel Frequencies** | 0.15-0.25 Hz | 0.3-0.7 Hz | Plugin is faster |
| **PPG Waveform** | Realistic with notch | Simple sine | Firmware is physiological |

| **Battery** | Linear discharge | Oscillating | Different behavior models |
| **Sync** | Random intervals | Fixed 1 Hz | Firmware more realistic |

## 9. Viewing in LFP Viewer

### 9.1 Why Aux Channels May Appear as Flat Lines

The LFP Viewer in Open Ephys has a default Y-axis range of approximately **±500 µV**. This works well for EEG signals (typically 10-200 µV), but the auxiliary channels use much larger values:

| Channel | DC Offset | AC Amplitude | LFP Viewer Result |
|---------|-----------|--------------|-------------------|
| EEG | 0 | ~100 µV | ✅ Visible, centered |
| AccelX/Y | 0 | ±1000 | ⚠️ Clipped at edges |
| AccelZ | 16,384 (1g) | ±500 | ❌ Way off screen (top) |
| PPG_Red | 100,000 | ±5,000 | ❌ Appears as flat line at top |
| PPG_IR | 120,000 | ±6,000 | ❌ Appears as flat line at top |
| PPG_Green | 80,000 | ±4,000 | ❌ Appears as flat line at top |
| Temperature | 3,650 | ±50 | ❌ Off screen (top) |
| Battery | 4,000 | ±200 | ❌ Off screen (top) |
| Sync | 0 or 1 | 0/1 | ⚠️ Barely visible (tiny amplitude) |

### 9.2 Why These Values?

The simulation uses **physically realistic values** that match real sensor outputs:

- **Accelerometer**: 16,384 counts = 1g (standard IMU scaling at ±2g range)
- **PPG**: Large DC offset represents ambient light + tissue absorption; small AC is the actual pulse
- **Temperature**: 3650 = 36.50°C in centi-degree units
- **Battery**: 4000 = 4000 mV = 4.0V (typical LiPo voltage)

These values are correct for **data recording and analysis**, but don't display well in a viewer optimized for microvolt-scale EEG.

### 9.3 How to View Aux Channels

**Option 1: Adjust Y-axis range in LFP Viewer**
- Click on a channel and adjust the range slider
- For PPG: Set range to ±200,000 or larger
- For Accel: Set range to ±20,000

**Option 2: Use separate viewer per data type**
- Route EEG to one LFP Viewer (default range)
- Route Aux to another LFP Viewer (larger range)

**Option 3: Apply DC removal filter**
- Add a High-Pass Filter before the viewer
- Cutoff: 0.1 Hz removes DC offset
- Aux signals become centered around 0

**Option 4: Normalize in post-processing**
- Record raw data with original scaling
- Normalize during offline analysis

### 9.4 EEG vs Aux Display Comparison


### 10.1 Development & Testing

- **UI Testing**: Verify LFP Viewer displays waveforms correctly

### 10.2 Demonstrations

- **Documentation**: Create screenshots and videos

- **Filter Testing**: Known frequencies make filter response easy to verify
- **Event Detection**: Sync pulses test trigger detection

### 10.4 Signal Quality Reference

| Expected | If Not Seen | Possible Issue |
|----------|-------------|----------------|
| Clear sine waves | Flat line | Buffer not filling |
| Correct frequencies | Wrong frequencies | Sample rate mismatch |
| Stable amplitude | Clipping | Gain too high |
| All channels present | Missing channels | Channel count mismatch |
